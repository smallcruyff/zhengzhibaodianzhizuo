# Codex / Claude Code 跨软件交接

`policy_revision: 1`
`effective_date: 2026-09-14`

用户最终选择Claude桌面软件的Code标签页、本地模式、同一个“gpt和claude共同的小窝”目录；Cowork保留为备用。这次配置不启动任何一册正文修订，不改变宪法、证据、结构和验收要求。

先读项目根`00_协作入口.md`。资料在`00_共同资料/原材料`，原件保留原位，通过本机同步脚本单向发布。Skill母版仍是Codex已安装技能；共同规则和`.claude/skills`为同版本发布副本。双方可提出候选，主代理核定后更新唯一母版并运行发布，不能分别维护两套规则。历史ZIP不是当前规则。每批开工和落笔前检查共享文件是否变化。

`Claude协作同步_20260914/books.json`只登记本册既有进度、审阅清单和工程入口，不替代其权威状态。运行`collab.py status --book 必修二`等命令读取即时文件，区分中央确认稿和最新候选。旧快照中的版本号和完成数不能覆盖实际新状态。

每本只设一个合稿负责人，使用`collab.py checkpoint / offer / accept`登记交接；每个负责人用软件名和实际任务ID组成唯一标识。原负责人先保存候选、进度、新要求、已合批次、未决、检查覆盖、下一动作、待用户回复和后台任务，处理仍可能写稿的任务后再offer；接手方核实父文件指纹后accept。程序的文件锁只串行化协作登记，不是操作系统写保护，不能阻止任意脚本直接写Word。每次实际合稿前必须再核负责人、父稿和原值，沿用本册原发布流程，不自动合并Word。

双方候选分别写本册工程`协作/候选/Codex`与`协作/候选/Claude`。未接管者可以读取、检查、产出独立候选，不修改另一方负责的中央状态和审阅入口。配置与测试不代表已把必修二或必修三交给Claude制作。登记为未核定的其他册先核实际工作头及依赖，不猜用历史包。

同一平台内并行的两条写入线（例如必修三书稿与题库Markdown转换）分别开独立侧边栏会话，各自登记写权；一方移交时写回执并用跨会话消息告知对方，此后不再写对方的线。

桌面源文件使用实际Mac路径；共同项目内路径尽量相对。Claude Code可从已授权路径读取必修三旧工程中的证据，已有外部证据副本只作缓存并按其清单标注验证范围。不要把复制状态当作全书证据或内容审查。

共同同步程序不会覆盖未登记文件或人工修改的副本，已登记旧副本可恢复归档；源文件删除仅报告，不传播删除。文件内容/元数据有变化时更新逐文件指纹。长任务每批保存检查点，切换前再保存；内部思考、聊天记忆和工具会话不宣称同步。

Claude Code的模型分工见[AGENTS](../AGENTS.md)。项目`.claude/agents`按sonnet、haiku配置，主代理保持用户所选模型。真实调用成功才登记已使用；工具缺失、权限拒绝或替换模型均如实保留。Word/PDF处理使用该宿主实际支持的文档与PDF技能或已核验本地脚本，不虚构导出方式。
