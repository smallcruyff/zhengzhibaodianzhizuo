## 从文件差分开始

从本册中央状态取得真实工作头，比较SHA；本轮只读原件，在同册工程目录保存候选、证据缓存和变更记录。第一次遇到题包完整枚举；以后只读取新文件或SHA发生变化的文件。复用同指纹、同题、用途适用的原文、图片、完整评分条件和人工核验记录；文件名相同不能证明内容未变。

使用 `scripts/source_intake.py 题包路径 --cache 本册工程缓存目录 --previous 上批清单.json --report 本批清单.json` 计算文件差分（首次省略previous），缓存PDF、PPTX、Word可提取文字并列出媒体、备注或空文本页。它不自动OCR、不判定E1、不把提取成功当已读原件；同SHA缓存可复用，原件路径与完整题卷身份仍须核实。

每卷记录完整学年、届别、考试日期、区县和考试类型。2027届试卷可能在2026年举行，不以下载年份、文件修改时间或文件夹名推断届别。学生版来源标题仍统一使用“年份＋区县＋考试类型”，不特殊加印日期/届别；例如2023年11月高三期中按原卷核定为2024届时列2024期中。详细考试日期和学年只留后台。2023题包只有答案而没有正式细则的卷，只处理选择题，不新增无细则主观题例外。题键沿用计数协议的完整卷身份＋题号＋小问。不同版本、改题号、改设问的卷先比原件，不能模糊合并。

对照实际书稿与现有证据，把每题处理为：

| 原件与书稿差分 | 本轮动作 |
|---|---|
| 相同题面、相同细则、已有合格落位 | 复用核验与落位，不重复插入 |
| 已有题面，新增正式细则或细则修订 | 主代理比较完整评分条件，只修改受影响教学与映射 |
| 题面同源但有校订 | 保留版本关系，按原卷核验后更新所有受影响落位 |
| 新题及合格评分证据 | 主代理确定已有考法中的局部插入位置，定稿教学后插入 |
| 暂缺证或身份冲突 | 保留该题未决；其他已闭合题继续。准入与例外仍按证据协议 |

筛卷同时检查原题与正式细则的实际得分角度，不仅按设问所限教材筛选。跨模块题若正式细则确有本书节点可用角度，按原题限制保留完整回答并作跨模块标识；不能把普通材料中的经济词或泛泛民生表述当成评分角度。选择题逐项检查题肢中的本书知识，不能以设问没有限定《经济与社会》就排除。2026丰台期末Q2①的“基本公共服务均等化”、期末Q17和二模Q17的“以人民为中心”、期末Q18的“政府积极履职＋维护市场秩序”，是这一检查的回归样例；二模Q11仅以市场经济作背景、实际考财产权法律规则，则不据背景词新增经济落位。

正文同题多节点落位可能各有教学用途，不能按题名全书去重。唯一题数、实际题块数、正式评分槽和节点频次分别维护。新的正式角度先拟合现有分类；需新增分类时由主代理判断结构授权是否覆盖，不由脚本自行造标题。

## 题肢单练按每一条准入

2026-09-12用户指出修订213题肢775（发展道路多样性）和781（直接提起劳动争议诉讼）跨模块混入，要求全量筛查。旧抽取代码已有逐条drill标记，但主代理曾把非经济项也标为收入；布尔标记及错因分类并不证明教材归属。完整原题的收录与题肢单练的收录是两个判断：正文原题保持全部选项；单练不能因整题含本册知识就整组抽取。先按原题、必要材料和答案判明每条题肢实际考点，再确认其在当前册已有知识节点的落点。题材出现企业、工资、生态、技术或民生，及分类标签“因果关系”“成立条件”，均不能单独证明属于本册。

必修二单练排除以国家主权、国际组织性质、现代化道路、党的历史、民族自治、诉讼与仲裁程序、具体民事权利、文化权益或纯哲学/思维方法为判断关键的题肢。经济只是这些判断的背景时不收；不能将“以人民为中心”或“创新”泛化为所有民生、司法或哲学题的通行证。另一方面，政府经济职能、基本公共服务、社会保障、劳动与分配、保护产权激发创新的经济作用，以及本书已认可的开放经济考法，不能按“政府”“法律”“国际”等关键词机械排除。混合题肢只有确有可独立教学的本册知识、并能完整解释整个判断时才保留，不能剪去其他半句制造一条新原题。

主代理核定逐条保留/排除清单，记录稳定题源身份、原选项身份或既有题肢书签、题肢原文、本册依据及排除理由。脚本不得把整题include标记自动传给全部选项；没有条目级准入的新增项不进入候选。来源SHA相同只复用原文与答案；准入规则修订或出现反例时，受影响题肢的旧准入必须重判。

单练只收用于知识辨析的题肢并只分正确/错误：知识、逻辑、主体、概念或程度上有错的判“错误”并写纠正；句子成立但仅材料未体现的不进单练；解析中的“不选”不搬入单练（用户2026-09-15裁定）。删除或补入后由同一保留清单生成/维护打印、答案与纠正、独立单练、来源台账；检查成对身份、文本、编号、分类实数与总量。仅删除单练行不减少正文完整题数，不删除原题选项。非本册项保留在后台排除清单；旧编号与新编号保持可追溯。交付前使用 `scripts/check_drill_admission.py --candidates 候选条目.json --decisions 主代理裁决.json --report 核验.json` 核对全部条目都有显式决策、原文和身份一致，并只输出准入项；该工具验证清单执行，不能代替教材判断。

回归检查同时覆盖负例和正例：发展道路多样性、劳动争议诉讼前置、文化基本权益、国际组织专门性应排除；劳动收入与社会保障、基本公共服务均等化、政府监管维护市场秩序应保留。反例修正要覆盖本轮要求的全部题肢及两层副本，不能只删用户举出的编号。

## 局部插入与排版维护

新图表除原图边界、列数、连接关系和全文外，还须对比原卷版心占比、图注相对字高、左右/上下关系；完整无裁切不代替比例核验。布局和自然段规则见版式协议。跨册开工和反复返工的处理见[制书工作流](book-production-workflow.md)。

将源题、图表和主代理定稿教学组成完整题块；复用当前节点相邻同类型题块的段落、字符及表格样式。保留自然段、小标题、强调、题号、分值和图表信息，不从PDF物理行直接复制硬换行。主观材料、设问和选择题字体分别沿用本书当前标准。复制字符样式时区分栏目标签、正文和标点；不要把标点的字符压缩比例、标签颜色或错项颜色扩散到整个新段。新图表核对原图边界、列数、连接关系和全文，不用文字提取结果代替版式判断。 材料小标题须与后续材料同页，表头须与至少一行表体同页；优先设置段落与下段同页，避免靠手工换页或缩字号补救。导出后检查这些约束是否生效。

收到代理明确完成回执后，再核对补丁文件SHA并冻结集成副本；不要边读边合仍在修改的模块。主代理追加句子或修正也先检查当前值，避免两端同时补同一句。

插入位置按既有节点内排序确定；仅调整受影响分类中的例题编号，不重排全书。锚点使用稳定书签或唯一题键与相邻内容，body索引必须同时绑定父SHA。复制题块须重建复制对象的书签、图形ID和媒体关系，保留既有对象；同一批次重复执行要能识别已导入，不能再次加题。

本技能的 `scripts/book_incremental.py` 提供当前必修二的确定性维护：

```text
inspect DOCX --report JSON
refresh DOCX --expected-sha SHA --scope 分类书签 --renumber --output 新候选.docx --report JSON
sync-pages DOCX --expected-sha SHA --pdf 同版导出.pdf --output 页码同步.docx --report JSON
```

- `inspect`从实际题块核对带“（N题）”的考法标题，提供题目标题、分类书签与范围；其标题键用于匹配提示，不替代完整题源身份或E1登记。默认不改文件。
- `refresh`按实际题块更新分类题量；加`--renumber`时更新明确指定分类的局部编号。可重复指定`--scope`；省略时仅检查和更新全书受支持分类的数量，不重编全书例题。分类内重复或空范围会报错，交主代理辨别。脚本支持“例题”“拓展例题”及当前HBMethod/Heading分类，不把选择题或未知新结构强行套入。独立选择题题量和题肢编号沿实际块型维护。
- `sync-pages`用实际PDF导航目标更新既有PAGEREF缓存，保持动态字段、书签和超链接。必须提供该候选实际导出的PDF；更新后再次导出并核对目录页码至稳定。Word自身的分页与其他排版引擎可能不同，不能将外部引擎的缓存说成Word已重新计算的页码。
- 修改命令要求输入SHA并输出新文件；只改`document.xml`，其他ZIP部件字节保持。标题改名或新增目录项需另作显式补丁；不由计数脚本猜测目录结构。

## 验证与交付

导出前，主代理先一次核定本批完整题表：每题的收录或排除理由、正式评分角度、已存在落位、新增或修订动作及未决。原题、评分、分类与教学反向核验通过，再查题键/分类题量/局部编号/书签关系，集中导出本批候选，避免每加一题重渲染整本。后续若发现真实漏题或转录反例仍须修正；不能为了省一次导出保留错误。全局分页或导航变化按AGENTS进行实际页图检查，复用合格、完全一致的旧页审阅证据；新增、重排及分页影响的页面须查看。不能只验“新题那一页”，也不能用生成页图代替读图。

在同一批次记录父SHA、来源SHA、题键、证据变化、实际落位增减、影响分类、字段变化及检查范围。保存真实文件后更新中央状态和固定审阅入口。已有未决仍保留；补入两卷不等于全书终审通过。

节省token主要来自复用题源缓存、脚本匹配计数、局部题块修改、合批渲染和明确分工；主代理仍须阅读新增评分依据并定稿教学。若大量插入引起后续多页重排，实际页面验收成本也会增加，不能承诺任意补题都只花固定少量token。
