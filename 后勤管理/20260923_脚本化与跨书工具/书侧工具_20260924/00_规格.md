## 三、apply_patch.py —— 按已批准补丁写 DOCX

子命令：
- `check --docx 父稿 --patch p.json [--report]`：全部 op 在原稿上定位与校验，不写。
- `apply --docx 父稿 --patch p.json --out 候选.docx [--report] [--health]`：check 全过才写；`--health` 对输入与输出各跑 `bh.run_health`，输出比输入多出的 FAIL 列入报告并退出 1（输出保留供查看）。
- `diff --old A.docx --new B.docx --out p.json [--book …]`：两版之间生成段落级补丁（用于核验外部回传“实际改了什么”，也用于回归：`apply(A, diff(A,B))` 的段落文字流应与 B 逐段一致）。

补丁格式（在工具文件头写成正式说明）：
```json
{"schema": "baodian_patch_v1", "book": "bixiu3", "parent_docx_sha256": "…",
 "approved_by": "claude:会话ID | codex:任务ID | user", "approval_ref": "台账编号或说明",
 "ops": [{"id": "P001", "op": "replace_text", "anchor": {...}, "old": "…", "new": "…", "reason": "…", "evidence": "…"}]}
```
- `anchor`：`text`（段落全文，归一后全等）或 `contains`（段内子串），可加 `style`、`prev`（前一段全文或子串）、`block`（所在例题标题子串，用 `bh.walk` 的例题块限定）、`index_hint`（原稿段号，只作消歧提示，不能单独定位）。**必须恰好命中一段**；0 段或多段 → 中止，并在报告里列出候选段（段号、样式、前后文）。
- op 种类：`replace_text`（old 为段内子串且恰好出现一次；跨 run 时新字放进起点 run、吞掉后续 run 里属于 old 的字，报告 `cross_run` 和被吞 run 的格式差异；可选 `new_format:{color,bold}` 让新字单独成 run）；`replace_paragraph`（old = 全段文字全等；保留 pPr 与首个文字 run 的 rPr；段内有图片、书签、域、超链接时拒绝，除非 `allow_complex:true`）；`insert_after`/`insert_before`（`paragraphs:[{text, style 或 clone_from, runs?:[{text,bold,color}]}]`，样式名须存在）；`delete_paragraph`（old 全段全等；含图片/书签或是表格单元格唯一段时拒绝，除非 `allow_complex`）；`set_format`（对 old 子串设 color/bold）；`set_keepnext`（true/false）。表格结构（增删行列）不在 v1 范围，写进 known_limits。
- 安全：所有 op 先在**原稿**上定位，互不依赖；同段多条 op 只允许不重叠的 replace_text/set_format，其余冲突中止。**题面零改写**：锚点段落在 `bh.walk` 标注的 `source`/`title` 区时，op 必须带 `source_zone: "restore" | "approved_edit"` 和 reason，否则中止。新文字过学生正文词表（house＋本册 engineering_tags、forbidden words、forbidden_word_groups）——命中即中止（source_zone=restore 除外）。**已应用检测**：old 不在而 new 恰在该段 → 标 `already_applied`；apply 时遇到它整批中止，不做部分重放。
- 写后复核：重开输出，逐条验证后置条件（新文字在目标段、段数变化＝插入−删除）、未点名段落 C14N 不变、其余 ZIP 成员不变；报告逐条给出段号、样式、区位、改前/改后文字与段落指纹。

必测：① 在 B3_52 上合成补丁，每种 op 至少 2 条，覆盖表格单元格段、带红色 run 的段、跨 run 的 old；② 负例全拒且不留输出：父稿 SHA 错、锚点 0/2 命中、old 不符、同段冲突、题面区未授权、新文字含工程词、输出落在审阅入口/必修二目录/Skill 目录、冻结册配置；③ 回归：`diff(B3_04, B3_52)` 应用到 B3_04 后段落文字流与 B3_52 逐段一致；`diff(B3_03, B3_04)` 同样；`diff(B3_51, B3_52)` 作压力测试，报告 op 数、耗时、复现率，复现不了的类型如实列出；④ 幂等：对输出再 check → 全部 already_applied；⑤ B2_230：check 可跑，apply 退出 3。

## 四、layout_prepare.py —— 编号、考法题数、keepNext、目录回填

- `repair --docx X --out Y [--numbering] [--method-counts] [--keepnext] [--toc --toc-pdf P] [--expect-sha S] [--report]`：各操作必须显式点名，只改点名的部分。

## 五、publish_review.py —— 发布到固定审阅入口

把 publish_b50/b51/b52、promote_b52、publish230、publish_batch 合成按配置（`publish.*`、`paths.*`、`naming.*`、`handoff.*`）运行的发布工具。
```
publish_review.py --profile bixiu3 --batch 53 --docx 候选.docx --pdf 候选.pdf \
  --acceptance 构建/最终主代理技术验收.json --actor claude:会话ID [--note 本轮修订与审查说明.md] [--apply] [--report]
```
- **默认 dry-run**：打印完整计划（每个要复制、归档、更新的文件及目标路径与 SHA）和全部门的结果，不写任何文件（报告只写临时目录或 构建/）。
